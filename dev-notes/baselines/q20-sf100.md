## Submitted plan shape

```
AdaptiveDatafusionExec
  SortExec: [s_name ASC]
    Projection: [s_name, s_address]
      DynamicJoinSelectionExec plan_id=3 LeftSemi(s_suppkey, ps_suppkey) repartitioned=false
        HashJoinExec CollectLeft Inner(n_nationkey, s_nationkey)   ← nation broadcast
          FilterExec n_name = CANADA
            DataSourceExec nation
          DataSourceExec supplier
        Projection: [ps_suppkey]
          DynamicJoinSelectionExec plan_id=2 Inner(ps_partkey=l_partkey, ps_suppkey=l_suppkey)
                                   filter=ps_availqty > 0.5·sum(l_quantity) repartitioned=false
            DynamicJoinSelectionExec plan_id=1 LeftSemi(ps_partkey, p_partkey) repartitioned=true
              ExchangeExec Hash([ps_partkey], 16) plan_id=4 stage_id=0    ← SPILLER
                DataSourceExec partsupp
              ExchangeExec Hash([p_partkey], 16)  plan_id=5 stage_id=1
                FilterExec p_name LIKE forest%
                  DataSourceExec part
            Projection: [0.5·sum, l_partkey, l_suppkey]
              AggregateExec FinalPartitioned gby=(l_partkey, l_suppkey) sum(l_quantity)
                ExchangeExec Hash([l_partkey, l_suppkey], 16) plan_id=6 stage_id=2   ← SPILLER
                  AggregateExec Partial gby=(l_partkey, l_suppkey) sum(l_quantity)
                    FilterExec l_shipdate in [1994-01-01, 1995-01-01)
                      DataSourceExec lineitem
```

At SF100 the filtered `part` is no longer trivially small; AQE opts for
a repartitioned `partsupp ⋈ part` join instead of broadcast, giving
**three** hash exchanges vs. one at SF10:

1. `partsupp` shuffled by `ps_partkey` (spills)
2. `part` filtered by `p_name LIKE 'forest%'` shuffled by `p_partkey` (small; no spill)
3. `lineitem` partial-agg shuffled by `(l_partkey, l_suppkey)` (spills)

Two of three hash-exchange stages spill; the biggest single spill event
is 152 MB.

## Goal

Drive `spill events → 0` (and `spill bytes → 0`) by replacing each
spilling Hash exchange with the post-shuffle range-filter pattern:
stage N ships TDigest sketches back to the scheduler via `#2175`,
scheduler picks globally-optimal cuts, and emits K stage N+1 tasks with
per-task literal `FilterExec` predicates covering disjoint ranges — no
cross-partition buffering in the shuffle writer.
