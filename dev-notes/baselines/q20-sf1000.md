# Q20 SF1000 baseline — pre-adaptive-range-shuffle

Captured 2026-07-25 on `brent/runtime-stats-transport-merge` @ `ca630937`,
release build, 2 local executors (16 GB memory pool each, 4 vcores each),
16 target partitions, AQE + adaptive-join + collect-statistics all enabled.

Note on cluster shape: the doc's SF1000 numbers
(`docs/source/contributors-guide/benchmarking.md`) are on 32 executors ×
64 GiB × 8 vCPU (r6i.24xlarge). This baseline is on 2 local executors ×
16 GiB × 4 vCPU — 1/64 of the doc setup, mostly for reproducibility on
the workstation, not for comparison to the cloud baseline. Wall clock is
meaningful; the memory-model pathology (spill bytes/event) is what
carries across cluster sizes.

## Submitted plan shape

Same shape as SF100 — three hash exchanges. Difference is which of the
three trigger spill:

```
AdaptiveDatafusionExec
  SortExec: [s_name ASC]
    Projection: [s_name, s_address]
      DynamicJoinSelectionExec plan_id=3 LeftSemi(s_suppkey, ps_suppkey) repartitioned=false
        HashJoinExec CollectLeft Inner(n_nationkey, s_nationkey)   ← nation broadcast
          ...
        Projection: [ps_suppkey]
          DynamicJoinSelectionExec plan_id=2 Inner(...) repartitioned=false
            DynamicJoinSelectionExec plan_id=1 LeftSemi(ps_partkey, p_partkey) repartitioned=true
              ExchangeExec Hash([ps_partkey], 16) plan_id=4 stage_id=0    ← SPILLER
                DataSourceExec partsupp
              ExchangeExec Hash([p_partkey], 16)  plan_id=5 stage_id=1    ← SPILLER
                FilterExec p_name LIKE forest%
                  DataSourceExec part
            Projection: [0.5·sum, l_partkey, l_suppkey]
              AggregateExec FinalPartitioned gby=(l_partkey, l_suppkey) sum(l_quantity)
                ExchangeExec Hash([l_partkey, l_suppkey], 16) plan_id=6 stage_id=2   ← SPILLER
                  AggregateExec Partial gby=(l_partkey, l_suppkey) sum(l_quantity)
                    FilterExec l_shipdate in [1994-01-01, 1995-01-01)
                      DataSourceExec lineitem
```

All three hash-exchange stages spill at SF1000 (vs. two at SF100 and one
at SF10) — even the filtered-`part` shuffle now pushes enough bytes to
overflow the per-task buffer. Biggest single spill event is 1.75 GB; any
executor with less than that much slack in its memory pool would have
OOM'd instead of spilling gracefully.

## Goal

Drive `spill events → 0` (and `spill bytes → 0`) by replacing each Hash
exchange with the post-shuffle range-filter pattern: stage N ships
TDigest sketches back to the scheduler via `#2175`, scheduler picks
globally-optimal cuts, and emits K stage N+1 tasks with per-task literal
`FilterExec` predicates covering disjoint ranges — no cross-partition
buffering in the shuffle writer.
